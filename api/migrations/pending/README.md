Migrations here are not applied: `python -m migrate` only reads `migrations/NNNN_*.sql`. They are unnumbered on purpose. Each ships one release after the migration that made it safe: at that release, move it up into `migrations/` under the next free number (for example `drop_legacy.sql` becomes `0006_drop_legacy.sql` if `0005` is the latest), once every server runs code that no longer uses what it drops. `drop_legacy.sql` follows `0003`.
